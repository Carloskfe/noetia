# NEM-025 B2 preparation: transactional-message matrix

Companion to [`README.md`](README.md). Code was read at Checkpoint A, `feat/nem-025-checkpoint-a` @ `81143790`, which contains `main` @ `8f2f294`. Line numbers refer to that commit. No email or push was sent while this was prepared.

**Abbreviations used in the tables**

- **ui** means `users.uiLanguage`, a `varchar(5)` column with default `'es'`.
- **"cast"** means the caller passes `(user.uiLanguage as 'es' | 'en') ?? 'es'`. This is a type assertion only. Any stored string reaches the template, and every template branches on `lang === 'en'`.
- **Esc** means the value goes through `EmailService.escape()`, which escapes `&`, `<` and `>` only. It does not escape quotes.

### Cross-cutting email facts

- **Fallback strings.** Templates and callers fall back to Spanish strings regardless of language: `Alguien`, `Un usuario`, `lector/a`, the occasion labels, and `Noetia` as a plan name. These must move into the dictionaries. The EN outputs of these fallbacks are **captured as-is** by the golden master. Any change to them is listed separately.
- **Brand terms.** `Noetia Token(s)` appears untranslated in both languages inside the gift card. *Token* is the canonical Spanish term (CLAUDE.md), so ES is correct. The fr-CA term is fixed by terminology decisions D-T1–D-T6 (PR #79).
- **Copyright year.** The footer year is `new Date().getFullYear()`. Golden-master tests must freeze the clock.
- **Logging.** All sends share `send()`. On failure it logs `Failed to send email to ${to}`, which writes the recipient address into logs (**X-8**).
- **Callers' error handling.** E-1, E-2, E-3, E-7, E-8 and E-9 `await` the send, but `send()` swallows errors, so callers never see a failure. E-4 adds `.catch(() => {})`. E-5 is `void`.

### Push facts verified

- **Empty bodies.** The three empty-body types come from `buildContent`'s `default` branch, which returns `{ title: 'Noetia', body: String(vars.message ?? '') }`. No caller passes `message`, so the body is always the empty string. Confirmed by reading all five call sites.
- **Tap handling.** Mobile registers on `MainNavigator` mount (`usePushNotifications.ts`). The tap handler is a no-op (*"future: navigate based on … data.type"*), so adding `data` fields changes no client behaviour.
- **Expo response.** The response is not inspected, so `DeviceNotRegistered` and other errors are silently ignored. On a network failure the **push token** is logged (`Push failed to ${to}`) (**X-10**).
- **Token cleanup.** Tokens are never deleted. There is no delete call anywhere in `services/api/src`, no logout call, and `push_tokens.userId` has **no foreign key**, so account deletion leaves the rows (**X-11**). One path is reachable after deletion: `gift_claimed` to a deleted buyer, because `gift_cards.buyerUserId` has no foreign key. See README §6.1, dependency **SP-1**, for verified facts V-1…V-12 and possible consequences C-1…C-4.
